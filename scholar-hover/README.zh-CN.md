# 知阅 · Google Scholar 文献悬停助手

在搜索结果上停留片刻，先看清论文，再决定是否打开。桌面 Chrome 扩展，用户自带模型 API Key，无产品账号和自建后端。0.3.1 支持简体中文、英语、法语和德语。

[English README](README.md)

**当前为可安装的原型测试版，尚未公开发布，也未完成人工验收。** 真实 Scholar 匹配、翻译质量及筛选价值仍需试用验证；GitHub 公开发布明确等待用户试用后的确认。四种语言的人工检查及母语使用者审核均尚未完成。本版见 [0.3.1 慢模型请求修复报告](docs/test-report-0.3.1.md)，收藏与下载见 [0.3.0 报告](docs/test-report-0.3.0.md)，多语言基础测试见 [0.2.0 报告](docs/test-report-multilingual.md)。不能把构造页面或元数据派生输入的测试结果当作真实 Scholar 匹配准确率。

## 安装与配置

1. 解压 `release/scholar-hover-0.3.1.zip` 到一个固定目录，不要只双击 ZIP。源码构建后也可直接使用本项目 `dist` 目录。
2. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角“开发者模式”。
3. 选择“加载已解压的扩展程序”，选择包含 `manifest.json` 的解压目录或 `dist`。
4. 点击扩展图标进入设置，选择界面语言和生成语言，填写模型 API 基地址、模型名称、API Key；阅读外发说明并勾选同意，保存时授予该模型域名访问权限。
5. 打开或刷新 `https://scholar.google.com/scholar` 的论文搜索结果，悬停标题约 500 毫秒。安装前已打开的 Scholar 页面需要刷新一次。

API 地址填写包含版本路径的**基地址**，例如服务商提供的 `https://api.example.com/v1`；程序会追加 `/chat/completions`。不要填写完整的 `/chat/completions` URL。模型名必须使用服务商给出的 API 模型标识。目前仅支持 Chat Completions 纯文本非流式接口，不承诺兼容所有模型服务。连接测试会发起一次很短的模型请求，可能计费。

升级已解压扩展时，把新包解压到原先加载的固定目录，在扩展管理页点击重新加载，再刷新 Scholar 页面。换一个目录重新加载可能会被视为另一扩展实例，需要重新配置。0.1.0 的设置和密钥存储规则保持兼容；旧译文缓存会失效，首次生成可能再次产生模型费用。从 0.2.0 升级不会主动清除配置或生成缓存。旧版 ZIP 保留，便于对照试用。

## 语言与使用方式

界面语言和生成语言分别设置。例如，界面可用法语，标题、摘要译文和一句话概述可用德语。两项均默认简体中文，旧版缺少语言字段或存储语言无效时也回退为简体中文。仅修改语言设置会保留原有密钥。

只改界面语言会继续复用已有生成缓存；改变生成语言会使用单独的缓存条目，因此英文结果不会被当作德文结果使用。原始标题、原始摘要及文献元数据保持原样，译文和概述按所选生成语言显示，不会用译文覆盖原始来源文本。

- 悬停先显示页面已有内容；公开索引查询完成后显示论文信息，模型生成完成后显示所选语言的标题、摘要译文及一句话概述。首次补全速度取决于网络与服务商，不能承诺即时生成。
- 卡片统一位于页面右侧，宽度 420 px（窄窗口自动限制），默认占满浏览器可见高度。拖动上下边框可调整高度，“恢复全高”可复位。正文支持滚轮、触控板和键盘滚动，标题及操作区保持可访问。鼠标离开标题后面板仍保留；未固定时点击其他位置可关闭；关闭按钮和 Esc 始终可用，固定后可专注阅读。
- 模糊匹配需要手动选定候选。明确预印本不会静默使用正式发表版；无法确认时保留原页面信息。缺少摘要只允许翻译标题，不编造摘要或研究概述。
- “匹配后自动生成”可关闭，改为点击生成。手动点击后自动固定卡片，按钮显示“正在生成…”并暂时禁用；结果返回后展示译文。底部持续显示进度或具体错误，失败后按钮恢复为“重试生成…”，也可通过始终可见的“设置”检查配置。连接测试最多等待 25 秒，完整生成的响应开始与内容读取分别最多等待 90 秒；失败不会自动循环调用模型。鼠标在元数据或缓存返回前已经离开论文时，插件不会在后台启动新的自动生成，重新进入卡片后才会继续。
- 默认 Key 仅保留本次浏览器会话；重启后重新填写。勾选本机保存后会持久保存，但这不是系统密码保险库。更换模型服务域名会清除旧模型 Key，必须重新填写；OpenAlex Key 不会发给模型服务。
- 缓存最多 200 条生成记录、7 天、4 MiB。论文内容、接口地址、模型、生成语言和提示词版本参与缓存指纹；不同模型或生成语言各占一条，缓存不跨用户同步。设置页可清空缓存或密钥。

## 缓存文章与批量导出

1. 在论文卡片点击“缓存本文”。保存元数据、来源、原摘要与已经生成的译文和要点；没有生成的字段明确标记，保存不会额外调用模型。同一篇再次点击更新已有条目，不改变首次保存顺序。后续生成会更新已缓存且内容一致的文章。
2. 点击“下载缓存文章”打开独立管理页。可删除条目、拖拽排序，或用上移/下移按钮。初始顺序为点击缓存的顺序；最终导出按整理后的顺序重新编号 1、2、3。
3. 点击管理页顶部的“下载缓存文章”。一个 `articles.md` 包含名称、作者、年份、期刊、原摘要、译文、摘要要点、来源、APA 风格引用及 BibTeX；同时尝试下载 `1-标题.pdf`、`2-标题.pdf` 等。文件保存在浏览器下载目录下的 `ScholarHover/时间-批次/`，每次导出是固定快照，之后调整列表不会改变已开始任务的编号。
4. 管理页按条目显示真实下载状态。没有已知 PDF、返回登录 HTML 或下载中断时明确提示；自动打开本批次首个失败条目的原文页面，其他失败项可点击原文/认证链接。完成登录、机构认证或验证码后可手动重试。插件不自动填写凭据或绕过认证；若只有文章页面、没有直达 PDF，需在原文页面自行下载。只采用匹配记录的主要出版版本，不静默下载其他预印本。

收藏独立保存在本机，最多 200 篇、4 MiB，不自动到期；“开始新的检索”会清空当前收藏（操作前确认），生成缓存的清空不会影响收藏。已下载文件不会因删除收藏而被删除。引用按现有元数据生成，缺失的卷期、页码不补造；BibTeX 使用通用 `misc` 类型，正式使用前请核对。0.3.0 新增 `downloads` 权限，用于上述显式下载及该批次状态检查。

## 数据与边界

元数据优先来自 [OpenAlex](https://help.openalex.org/api/)，必要时由 [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 按相同 DOI 补充摘要。来源由程序记录，生成模型不能修改来源。扩展允许选填自己的 OpenAlex Key；服务可用性与限额取决于服务商，遇到限流应稍后重试或使用自己的许可额度，不绕过限流。

插件只增强当前浏览的 Scholar 搜索结果，不自动搜索或翻页；原文下载只在收藏管理页主动导出时进行。隐私说明提供 [简体中文](docs/privacy.md)、[English](docs/privacy.en.md)、[Français](docs/privacy.fr.md) 和 [Deutsch](docs/privacy.de.md)。清单中的 `optional_host_permissions: ["https://*/*"]` 只提供自定义模型域名的申请范围，实际在保存时请求该服务的精确域名，并非安装时读取所有网站。

本版不包含 JIF、PDF 精读、文献库同步、其他检索网站、收费系统或自动遥测。JIF 必须取得适用于公众产品的数据授权后另行接入，期刊指标也不能替代单篇论文评价。

## 开发与复现

需要 Node.js 22 或更新的受支持版本，使用 npm 锁文件安装。安装依赖和浏览器需要联网；依赖齐全后，下列测试使用本地夹具。

```sh
npm ci
npm test
npm run test:corpus
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
npm run package
```

`test:e2e` 在临时、隔离的 Chromium 配置中加载真实 `dist` 扩展，使用离线 Scholar 页面和 API 响应夹具，不调用真实 Scholar 或付费模型。权限申请与拒绝逻辑有自动测试，浏览器测试使用受控权限边界，尚未验证真实 Chrome 授权对话框。截图和计时保存于 `test-results`。先构建再运行 E2E；修改源码后需重新构建。当前结果与适用范围见 [0.3.0 测试报告](docs/test-report-0.3.0.md)。

`npm run package` 输出可解压加载的 ZIP 与 SHA-256 校验文件，不签名、不上传商店。[商店介绍草稿](docs/store-listing.md) 已准备。正式发布仍需审阅试用结果和发布材料；GitHub 公开发布等待用户试用后的明确确认。

## 人工评估入口

[100 条固定真实文献样本](evaluation/corpus-100.json) 已保留来源和采集时间，但其中的 Scholar 输入是从元数据派生，**不是从 Scholar 观察得出的人工真值**。请按 [评估说明](evaluation/README.md) 核对并记录实际输入、两位审核者结论，以及翻译中的数字、否定和结论强度。该语料不证明任何一种语言已经完成人工检查或母语使用者审核。

```sh
node scripts/collect-corpus.mjs
node scripts/evaluate-corpus.mjs
node scripts/evaluate-corpus.mjs --require-human-review
```

默认采集命令只检查已有文件；只有显式 `--refresh` 才重新联网采集。人工审核未完成时，评估器报告 `NOT VALIDATED`，严格模式以退出码 2 结束。目标为 100 条中至少 80 条正确自动匹配、零错误自动匹配，摘要覆盖率独立报告；这些是验收目标，不是已取得的结果。
