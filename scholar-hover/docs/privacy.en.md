# Scholar Hover · Privacy notice

Version 0.5.0 (local version, unpublished) · 2026-09-26

[简体中文](privacy.md) · [Français](privacy.fr.md) · [Deutsch](privacy.de.md)

The extension starts OFF. After the user turns ON in the toolbar popup and explicitly grants optional `https://*/*` access to all HTTPS websites, it reads hovered or focused link text and destination URLs on supported HTTPS pages, including Google Scholar, Nature and arXiv. Scholar results also supply existing paper fields. A 500 ms hover or focus activates lookup; untriggered links are not sent to external services in bulk. Supported already-open pages receive the script without refreshing, but `chrome://`, the Chrome Web Store, native PDF viewers and pages restricting extensions are unsupported. OFF stops new previews, keeps saved content and may leave already-requested jobs running. It does not automate searches or pagination; downloads are explicitly exported by the user. There is no product account or project server.

## Where data is sent

- The original website receives a request for the triggered destination’s public HTML after the archive is checked by its exact normalized URL. Different labels for that URL reuse the preview. The all-HTTPS grant obtained when enabling previews also allows these source reads; access is no longer limited to one publisher. arXiv abstract, PDF and HTML links retain explicit revisions. Nature extraction requires verifiable paper identity and an explicit Abstract section. Citation metadata and explicit `ScholarlyArticle` abstracts are parsed locally. Requests omit cookies, login credentials, OpenAlex keys and model keys. Full pages never go to models. Generic descriptions are not full abstracts; arbitrary PDF text is not extracted, and source scripts, sign-in flows and redirects are not executed.
- OpenAlex receives a DOI or verified title only for identified scholarly papers. Abstract supplementation requires matching identity and publication kind; arXiv manuscripts and explicit revisions are not replaced by index records. Arbitrary links without scholarly metadata never trigger an index title search using their labels. An optional OpenAlex key goes only to api.openalex.org.
- Crossref receives the DOI when an index fallback needs to supplement a missing abstract for the same paper.
- The model service configured by the user receives the current paper's title, retrieved abstract and translation instructions for the selected output language only after configuration and consent to external transmission. Without an abstract, only the title and translation instructions are sent; no abstract or summary is generated. The model API key is sent only to the configured HTTPS service address. The provider determines its own data retention rules.
- Automatic mode can call the model after a qualifying hover and may incur charges. Generation can instead require a click. Choosing **Save paper** also requests background completion, even when automatic hover generation is disabled; model calls still require existing consent, a valid key and model-domain permission. Matching saved results are reused. Closing the card or page tab does not cancel completion of saved papers or guarantee cancellation of charges already incurred at the provider.

For arbitrary links without scholarly metadata, only an explicit click translates the link title; no abstract is generated.

Interface and output languages can independently be set to Simplified Chinese, English, French or German; both default to Simplified Chinese. Language settings are stored locally. Changing only the interface language reuses the generation cache; different output languages use separate cache entries. Translations do not overwrite the original paper information.

## Local storage

Keys are stored in the extension's browser session storage by default and are cleared when the browser restarts. If local key persistence is selected, keys are saved in local extension storage. This is not a system password vault or a promise of encrypted custody. Keys are not written to web pages, sync storage, analytics or logs, and page content scripts cannot read key storage. Keys can be cleared at any time.

Paper previews, matching candidates and generated results are archived only in local IndexedDB. The extension applies no expiry or automatic eviction at 200 entries / 4 MiB to this archive; browser storage quotas still apply. Different models or output languages use separate records, and reuse requires a matching content and configuration fingerprint. The archive does not sync across devices. Version 0.4.0 migrates existing generated-text caches and removes the old copies only after the archive transaction commits; migration failure retains the originals. Unrecognized old records are retained as raw copies and are not guaranteed to be reusable translations.

In 0.4.1, eligible old previews without an abstract, candidates or user confirmation, including stored HTTP 429 failures, can try the new retrieval path when reopened. Complete abstracts and reusable paid translations are retained. **Read abstract again** retries retrieval; **Retry generation** retries the model. A newly retrieved abstract changes the input, so a title-only translation cannot satisfy it. Model calls after retrieval still follow the generation setting, consent and configuration; saved failures can be retried explicitly.

**Clear cache** removes preview and generation archives; **Clear keys** handles credentials separately. Saved papers must be removed or cleared from their separate collection. Uninstalling the extension deletes its local storage; browser data clearing or storage failures can also affect the archive, so it is not a backup. These operations cannot delete data already received by a service provider.

## Permissions and controls

Previews start OFF on first installation or when first upgrading from 0.4.x. Later reloads and browser restarts retain the switch setting. Turning ON in the toolbar asks Chrome for optional `https://*/*` access to all HTTPS websites to read hovered-link text and destination metadata; installation alone does not grant that range. OFF stops new previews, retains saved content and may leave initiated jobs running. Revoke already-granted site access in Chrome’s extension settings if desired. OpenAlex and Crossref supplement scholarly metadata; model-domain access is managed through configuration. An all-HTTPS grant can already cover the model domain, but never replaces model data-sharing consent. The `offscreen` permission supports waiting for model responses and parsing public HTML locally in an extension-owned hidden page. Source scripts are not executed; full pages never go to models. Model keys go only to the configured endpoint and are never written into web pages.

This version has no ads, automatic telemetry or background uploads of usage records. Test diagnostics are stored locally; inspect them before sharing. Model output may be incorrect. Abstract translations and summaries identify their source basis and cannot substitute for conclusions from the full paper or a paper quality score. Live-page trials, human review including native-speaker review in all four languages, and controlled user evaluation of paper-screening effectiveness remain incomplete.

This notice describes the unpublished local 0.5.0 version. The public download remains the [0.4.0 experimental release](https://github.com/Jerrywjr/scholar-hover/releases/tag/v0.4.0). Report problems through [GitHub Issues](https://github.com/Jerrywjr/scholar-hover/issues). The project has not been submitted to or listed in the Chrome Web Store; future publication must provide a matching public notice. See the [0.5.0 test report](test-report-0.5.0.md) for verification boundaries: browser fixtures pre-grant HTTPS access and do not validate Chrome’s native permission dialog.

## Explicit saving, background completion and export

**Save paper** first writes the available page information to a separate local collection, then queues matching, abstract lookup and generation using the existing model configuration. The collection is limited to 200 papers and 4 MiB without automatic expiry. Records remain until removed, cleared or the extension is uninstalled. Clearing preview and generation archives does not clear this collection. Saving the same result again preserves its first-save order and does not restart a failed job; later results update only a saved entry that still exists and matches the source content.

Completion continues after the page tab closes while the browser is running. After a browser or background-worker restart, queued jobs and metadata lookups can resume. Jobs that had entered model generation first look for a reusable result; without one they are marked **Interrupted** and require a manual retry because the previous request may have been charged. Failed model requests are not retried automatically. Missing configuration requires user action, and uncertain matches require candidate confirmation. Session-only keys must be entered again after a browser restart.

Export Markdown and originals uses the downloads permission to create a Markdown file and attempt known full-text PDF downloads. Incomplete papers can be exported with a visible warning and marked missing fields. Export captures the current state; later completion does not rewrite exported files. Requests go to the full-text provider and Chrome includes existing cookies for that site; model and OpenAlex keys are never sent there. Full text is not sent to a model for analysis. Failed or unavailable PDFs show a reason; the first failed source page in each batch opens automatically, with links for the others. Users complete sign-in, institutional authentication and CAPTCHA themselves.

The latest batch filenames, source links and transfer states are stored locally for checking and retry. Non-PDF responses are not marked successful; the extension attempts to remove only that invalid file newly created by the batch. Normal exported files remain in the browser download directory after collection deletion, cache clearing or extension removal. Background completion requests only the source websites, metadata services and model services described above; it does not upload usage history or telemetry.
