# 0.4.0 预览归档与立即收藏验证报告

日期：2026-09-16。范围是保留已取得的信息、避免重复付费生成，以及立即收藏后由后台补全。公开 GitHub 发布继续等待用户试用确认。

## 行为变更

- 查看过但未收藏的论文也有本机归档；元数据与当前配置对应的译文在一次本地读取中恢复。页面区分未查看、已查看、已收藏，并从本机数据恢复这些状态。
- 取消预览/译文归档原有的 7 天、200 条和 4 MiB 自动淘汰规则；改用扩展自身的 IndexedDB。旧缓存先事务迁移再清理原副本，无法识别的旧结构也保留原始记录。浏览器配额、手动清除和卸载仍是实际存储边界。
- “缓存本文”先写入独立收藏，再排队补全元数据与译文。关闭搜索标签页后继续处理；重复保存保持顺序，不启动重复任务。独立收藏仍限制 200 篇 / 4 MiB，超限明确失败，不淘汰原收藏。
- 后台候选不确定时等待确认；配置不足或失败时保留条目并显示重试。浏览器/后台重启恢复尚未进入生成的任务；已有生成结果优先复用，没有结果的中断模型请求需手动重试，避免再次自动计费。
- 清空预览归档不删除独立收藏。当前配置的已存译文即使没有 Key 或模型网站权限也可读取；读取失败不会被当作“没有缓存”再发付费请求。
- 未完成条目允许导出，管理页明确提示缺失内容。已导出的文件是当时的快照，后续补全不会自动改写下载文件。

## 自动化证据

单元及 DOM 测试覆盖缓存迁移失败、长期保留、超旧限额、身份与出版版本区分、先保存后补全、跨标签页/预览与收藏共享请求、缺少 Key、候选确认、失败人工重试、后台恢复、删除重存，以及语言/候选切换后旧成功或失败不能覆盖新任务。页面测试同时覆盖悬停预取与保存之间的竞态、焦点、滚动和管理页排序。

浏览器测试加载真实构建后的 Manifest V3 扩展，使用隔离的 Chromium 配置、本地 Scholar 页面、元数据模拟和本机 HTTPS 模型服务；未调用用户的模型服务或 Key。核心检查包括：

1. 阻塞元数据请求期间点击保存仍先得到本机保存确认；随后关闭 Scholar 标签页，管理页从生成中变为已完成。
2. 只预览并生成、从未收藏的论文，在新标签页与真实浏览器重启后恢复完整译文，元数据及模型请求数均不增加。重启后的会话 API Key 确认已为空。
3. 在真实 IndexedDB 中迁移过期的旧缓存，确认生成结果及原始备份存在，提交后才移除旧 storage 副本。
4. 确认 31 秒后才开始响应的非流式模型请求仍可完成；保留已有侧栏、语言、下载、编号及登录失败处理验收。

最终验证：`npm test` 通过 287 项测试（16 个文件）；`npm run typecheck` 和 `git diff --check` 通过；`npm run build` 构建成功。最后一轮真实扩展浏览器检查通过 87 项，记录时间为 `2026-09-16T08:25:07.275Z`。重启后的状态徽标在悬停前正确显示已收藏、已查看或未查看，且不触发元数据或模型请求。

在本机模拟服务下，阻塞元数据期间的保存确认耗时 82 ms；20 次已缓存卡片首帧测量中，500 ms 悬停计时结束后的额外延迟 p95 为 6.9 ms。这是该设备与测试页面的结果，不代表所有设备或真实外部服务速度。逐项结果、下载核对文件与截图位于本机 `test-results/e2e.json` 和 `test-results/`，不纳入公开源码。

交付为 `release/scholar-hover-0.4.0.zip` 及同名 `.sha256` 校验文件；ZIP 是可解压加载的扩展，不含用户密钥或测试浏览器配置。

## 限制

这些检查验证的是本机流程、请求次数和状态一致性，不能证明真实模型始终可用、翻译正确或 Scholar 匹配达到目标准确率。固定语料的人工核对、数字/否定/结论强度审查及目标用户试用仍需按原方案完成。法语与德语界面尚无母语使用者审阅结论。存储空间不足会提示保存失败；浏览器重启时无法保证仍在服务商执行的请求未计费。

升级请覆盖原加载目录中的文件、重新加载扩展并刷新 Scholar；更换目录或卸载后重新安装可能失去原扩展实例的存储关联。
