# 知阅 · 文献悬停助手隐私说明

版本 0.4.1（本地修复，尚未发布）· 2026-09-23

[English](privacy.en.md) · [Français](privacy.fr.md) · [Deutsch](privacy.de.md)

本插件仅增强用户打开的 https://scholar.google.com/scholar 搜索结果页。它在本机读取当前页结果的标题、作者、年份、发表载体和链接，用于识别论文并显示“未查看”“已查看”“已缓存”状态；不会把未触发的结果批量发送给外部元数据服务。只有用户触发预览或主动缓存的论文才会按下述规则查询外部服务。插件不自动搜索或翻页；原文下载仅由用户在收藏管理页主动发起，不建立产品账号或自建服务器。

## 数据发送到哪里

- 原文网站：先检查本机归档，再按用户触发的论文链接请求公开 HTML。arXiv 的摘要、PDF、HTML 链接转换为摘要页并保留明确版本号；其他出版社须已有该网站权限，或由用户在扩展的原文网站授权页单独授予。请求不携带 Cookie、登录凭据或 API Key。公开 HTML 中的论文引用元数据、arXiv 摘要区或 `ScholarlyArticle` 明确摘要在本机解析，并核验论文身份；普通网页描述不作为完整摘要，不提取任意 PDF 正文，不执行网页脚本、自动登录或跟随跳转。
- OpenAlex：普通原文来源无法读取或缺少摘要时，发送该论文的 DOI 或标题以补全文献信息。已有原文身份的摘要补充须符合相同 DOI 和发表类型；arXiv 稿件及明确版本不会由索引记录替换。填写 OpenAlex Key 时，Key 只发送给 api.openalex.org。
- Crossref：回退查询中，必要时发送 DOI，补充同一论文的缺失摘要。
- 用户配置的模型服务：仅在完成配置并同意外发后，发送当前论文标题、取得的摘要和所选生成语言的翻译指令。无摘要时只发送标题及翻译指令，不生成摘要或概述。模型 API Key 只发送给用户配置的 HTTPS 服务地址；服务商自身的数据保留规则由其提供。
- 使用自动模式会在有效悬停后调用模型并可能产生费用；可切换为点击生成。主动点击“缓存本文”也会请求后台补全，即使悬停自动生成已关闭；模型调用仍需已有外发同意、有效 Key 和模型域名权限。已有匹配结果会复用。关闭卡片或 Scholar 标签页不取消已保存论文的补全任务，也不保证撤销服务商已开始的计费。

界面语言和生成语言可分别选择简体中文、英语、法语或德语，默认均为简体中文。语言设置保存在本机。只改界面语言会继续复用生成缓存；不同生成语言使用不同缓存条目。原始论文信息不会被译文覆盖。

## 本机存储

密钥默认存储于扩展的浏览器会话存储，浏览器重启后清除。选择在本机保存密钥后，密钥保存到本机扩展存储；这不是系统密码保险库或加密保管承诺。密钥不写入网页、同步存储、分析统计或日志，网页内容脚本不能读取密钥存储。可以随时清除密钥。

论文预览信息、匹配候选及生成结果只保存在本机 IndexedDB 归档，不设置时间到期或 200 条 / 4 MiB 自动淘汰规则，仍受浏览器存储配额限制。同一论文的不同模型或生成语言结果分别保存，仅复用内容与配置指纹匹配的结果，不跨设备同步。升级到 0.4.0 时会迁移旧生成缓存，归档事务提交后才清理旧副本；迁移失败保留旧记录。无法识别的旧记录保留原始副本，不保证可以直接复用为译文。

0.4.1 会让符合条件的旧缺摘要预览（例如已存的 HTTP 429，且没有候选或人工确认）在再次打开时尝试新读取流程；完整摘要和可复用的付费译文保留。“重新读取摘要”重试原文查询，“重试生成”重试模型；取得新摘要后，旧标题译文不再满足新输入。取得摘要后的模型调用仍遵循用户生成设置、外发同意和配置，收藏失败则可手动重试补全。

“清空缓存”清除预览与生成归档，“清除密钥”仅处理密钥；独立收藏需另行删除或清空。卸载扩展会删除其本机存储，浏览器清理数据或存储故障也可能影响归档，因此归档不等于备份。上述操作不能删除服务商已经接收的数据。

## 权限与控制

悬停卡片只在 Scholar 论文搜索页运行。`https://arxiv.org/*` 是读取 arXiv 摘要页的必需域名权限；OpenAlex 和 Crossref 权限用于回退查询。其他出版社通过“允许读取原文网站”打开扩展授权页，由用户确认当前一个来源域名；自定义模型域名在保存模型配置时单独授权。可选 HTTPS 域名范围不等于安装时取得全部网站权限。`offscreen` 权限既用于等待较慢的模型回复，也用于在扩展自有隐藏页中本地解析已取得的公开 HTML 文档结构；不会执行原文脚本或把整个网页交给模型。模型 Key 只发往配置的模型地址。

本版本不含广告、自动遥测或后台使用记录上传。测试诊断仅保存到本地；分享诊断前应自行检查。模型输出可能出错，摘要译文和概述均标注依据，不能作为论文全文结论或质量评分。真实页面试用、四种语言的人工与母语使用者审核，以及文献筛选效果的用户对照验证尚未完成。

本文描述尚未公开发布的本地 0.4.1 修复；公开下载仍为 [0.4.0 开源试验版](https://github.com/Jerrywjr/scholar-hover/releases/tag/v0.4.0)。问题反馈与公开联系渠道为 [GitHub Issues](https://github.com/Jerrywjr/scholar-hover/issues)。本地修复未发布到 GitHub Releases，项目也尚未提交或上架 Chrome Web Store。未来发布时须让公开隐私说明与所发布版本的数据流一致。

## 主动缓存、后台补全与导出

点击“缓存本文”先把已有页面信息写入独立本机收藏，保存成功后再排队核对论文、查找摘要并按已有模型配置补全译文。收藏最多 200 篇、4 MiB，无自动到期；直到用户删除条目、清空列表或卸载扩展。清空预览与生成归档不影响这份收藏。重复保存保持首次顺序，不会重启失败任务；后续结果只更新仍存在且源内容相符的收藏。

浏览器运行时，关闭 Scholar 标签页后补全继续。浏览器或扩展后台重启后，排队与元数据查询阶段可恢复；已进入模型生成的任务先查找可复用结果，没有结果则标为“已中断”，需人工重试，因为上次请求可能已计费。模型失败不自动重试；缺少配置时等待用户处理，候选不确定时等待用户确认。浏览器重启后，未选择本机保留的会话 Key 需要重新填写。

在管理页主动发起 Markdown 与原文导出后，使用 downloads 权限生成 Markdown 文件并尝试下载已知的原文 PDF。未完成的条目也可导出，界面会提示，缺失字段保持标记；导出固定当时内容，之后补全不改写已导出的文件。请求发送到原文提供方，Chrome 会携带该站点已有的 Cookie；模型和 OpenAlex 密钥不会发送给原文站点。原文不发送给模型分析。下载失败或无法取得 PDF 时，会提示原因并自动打开本批次第一个失败条目的原文页面，其他条目可逐一打开；登录、机构认证和验证码由用户完成。

最新批次的文件名、原文链接及下载状态保存在本机，用于核对和重试。返回非 PDF 的下载不会标为成功，并尝试删除该批次刚创建的无效文件。正常导出的文件保存在浏览器下载目录；删除收藏、清空生成缓存或卸载插件不会删除这些导出文件。后台补全仅按上述规则请求原文网站、元数据及模型服务，不上传使用历史或遥测。
