## 简短说明

在 Google Scholar 搜索结果中悬停查看论文元数据、来源摘要与可选的译文和概述。

## 详细说明

单一用途：帮助读者在当前 Google Scholar 搜索结果中预览有来源的论文信息，辅助筛选要打开的论文。

本地 0.4.1 支持简体中文、英文、法语和德语。界面语言和译文语言分别选择，后文中的生成内容使用用户选定的语言。多语言文本尚未完成母语使用者审核。

知阅 · 文献悬停助手仅在 `scholar.google.com/scholar` 的搜索结果页工作。将鼠标悬停在论文标题上，扩展先读取本机预览归档；没有可用信息时优先读取该结果的原文链接。arXiv 摘要、PDF 和 HTML 链接会转换为摘要页并保留明确版本号。其他公开网页支持可核验的论文引用元数据和 `ScholarlyArticle` 明确摘要；普通网页描述不当作论文摘要。普通原文无法读取或缺摘要时才回退查询 OpenAlex，必要时用 Crossref 补充；arXiv 版本不被索引结果替代。卡片显示论文标题、作者、年份、来源、取得的摘要，以及可能的匹配提示。结果不确定时，扩展会要求你手动确认候选论文。当前页的查看与缓存状态徽标只读取本机数据，不为全部结果发起外部查询。

你可以选择配置自己的模型服务地址、模型名称和 API Key（BYOK），并在明确同意后生成所选语言的标题、摘要译文和概述。没有填写 Key 或没有同意发送数据时，扩展不会自动调用模型服务；仍可查看页面与公开索引提供的文献信息。Key 默认仅保存在本次浏览器会话中；可由用户主动选择在本机设备保留。更换模型服务域名会要求重新确认并重新填写 Key。

预览面板固定在页面右侧，默认全高，可拖动上下边框调节高度。预览信息和译文在本机 IndexedDB 归档，不按时间、200 条或 4 MiB 自动淘汰，仍受浏览器存储配额限制；升级时迁移已有生成缓存，迁移失败保留原记录。设置页可清空归档。

点击“缓存本文”先把页面已有信息写入独立收藏，再在后台补全匹配、摘要和译文。主动收藏即使在关闭悬停自动生成时也会请求补全；调用模型仍需已同意外发、有效 Key 与模型域名权限，并可能计费。重复保存保留首次顺序，已有结果会复用。收藏最多 200 篇 / 4 MiB，清空预览归档不会删除收藏。

浏览器仍运行时，关闭 Scholar 标签页后任务继续。浏览器或扩展后台重启后，未进入模型生成的排队/查询任务会恢复；已进入生成的任务先复用匹配结果，无可用结果时提示“已中断”，需人工重试，上次请求可能已计费。缺少配置、模型失败或匹配不确定会在管理页显示，分别由用户配置后重试、主动重试或确认候选，不自动重复调用失败的模型请求。

“下载缓存文章”打开管理页，可删除、排序，再导出一份包含 APA 风格引用和 BibTeX 的 Markdown，并尝试下载同编号的原文 PDF。未完成条目也可以导出，界面会提示，缺失内容保留标记；后台后来补全不会改写已导出的文件。下载遇到登录或认证时提示用户处理，不绕过访问限制。

当前版本不提供 JIF 或其他期刊影响力指标。原文下载由用户主动发起，不进行全文模型分析或自动搜索翻页，不能替代文献核对或学术判断。

缺摘要和旧元数据 HTTP 429 可通过“重新读取摘要”重试来源；“重试生成”只重试模型。符合条件的旧缺摘要预览重新打开时会尝试新读取流程，完整摘要及可复用付费译文保留，不要求清空缓存。公开原文请求不携带 Cookie、登录凭据或 API Key；不执行网页脚本、登录或跳转，不解析任意 PDF 正文。主动导出的 PDF 下载仍可能由 Chrome 携带该站点已有 Cookie，模型和 OpenAlex 密钥不会随之发送。

## 权限用途

| 权限或访问范围 | 用途 |
| --- | --- |
| `storage` | 在本机保存设置、可选的 Key、主动收藏的论文、补全状态及最近一次导出状态；预览与译文归档另存本机 IndexedDB。 |
| `downloads` | 用户主动导出 Markdown 与原文、检查本批次下载状态；发现返回非 PDF 的无效文件时仅清理该批次刚创建的文件。 |
| `offscreen` | 在扩展自有隐藏页中本地解析已取得的公开 HTML 文档结构，并通过专用 Worker 等待较慢的模型生成；不执行原文脚本，不向模型发送整个网页。 |
| `https://scholar.google.com/scholar*` | 仅在 Google Scholar 搜索结果页识别标题并显示悬停卡片。 |
| `https://arxiv.org/*` | 必需域名权限，用于读取当前结果对应的 arXiv 摘要页并保留明确版本。 |
| `https://api.openalex.org/*` | 普通原文来源无法读取或缺摘要时，回退查询公开论文元数据与摘要。 |
| `https://api.crossref.org/*` | 回退查询中按相同 DOI 补充缺失摘要。 |
| 用户选择的 HTTPS 原文网站 | 通过“允许读取原文网站”打开扩展授权页，经用户确认后只授予当前来源域名；不申请所有网站权限。 |
| 用户选择的 HTTPS 模型服务域名 | 仅在用户保存配置、授予该精确域名权限并同意后，发送论文标题与原文摘要以生成译文与概述。 |

## 审核者测试步骤

1. 按项目 README 加载已解压扩展，在 Chrome 扩展管理页确认扩展已启用且设置页可以打开。
2. 打开 `https://scholar.google.com/scholar?q=machine+learning`，将鼠标悬停在任一结果标题约半秒。确认右侧面板显示公开元数据与来源，默认全高，边框可调整高度。
3. 将鼠标移入卡片，确认卡片不会立即消失；使用“固定”可保留当前卡片；按 `Esc` 可关闭。
4. 在卡片中点击“设置”。不填写 API Key、不勾选同意项时，确认不会自动生成译文与概述。
5. 在设置页填写测试用的 HTTPS 模型服务地址、模型名称和用户自己的测试 Key。勾选外发同意项后保存，Chrome 应仅请求该模型域名的访问权限。拒绝权限后配置不应保存；再次保存并授权可继续测试。
6. 保存配置后关闭“匹配后自动生成”，返回 Scholar，在信息尚未补全时点击“缓存本文”。确认条目先保存，管理页再显示补全进度，关闭 Scholar 标签页后仍会继续。主动收藏补全、点击生成和连接测试都可能由模型服务计费。
7. 再次打开同一结果，确认已归档内容可复用；重复保存不改变首次顺序。检查配置缺失、模型失败和匹配不确定时分别显示明确提示，失败后不自动重复请求；补全恢复与人工重试遵循上述规则。
8. 在设置页使用“清空缓存”和“清除密钥”，确认归档与密钥分别清除，已有收藏不因清空归档丢失。
9. 在普通出版社结果中使用“允许读取原文网站”，核对授权页仅申请当前域名；拒绝后不得读取该网站，允许后返回 Scholar 再读取。用 arXiv 的带版本 PDF/HTML 链接核对摘要来源及版本保持一致。对旧 HTTP 429 记录检查“重新读取摘要”，并确认完整缓存译文仍可复用。
10. 保存两篇论文后打开收藏管理页，调整顺序并导出，核对 Markdown 编号与 PDF 文件名前缀相同。对尚未完成的条目确认有导出提示、缺失字段标记；下载失败有原因和原文链接。
