## 简短说明

在 Google Scholar 搜索结果中悬停查看论文元数据、来源摘要与可选的译文和概述。

## 详细说明

单一用途：帮助读者在当前 Google Scholar 搜索结果中预览有来源的论文信息，辅助筛选要打开的论文。

0.3.0 支持简体中文、英文、法语和德语。界面语言和译文语言分别选择，后文中的生成内容使用用户选定的语言。多语言文本尚未完成母语使用者审核。

知阅 · 文献悬停助手仅在 `scholar.google.com/scholar` 的搜索结果页工作。将鼠标悬停在论文标题上，扩展会显示一个文献卡片：论文标题、作者、年份、来源、公开索引中的摘要，以及可能的匹配提示。结果不确定时，扩展会要求你手动确认候选论文。

你可以选择配置自己的模型服务地址、模型名称和 API Key（BYOK），并在明确同意后生成所选语言的标题、摘要译文和概述。没有填写 Key 或没有同意发送数据时，扩展不会自动调用模型服务；仍可查看页面与公开索引提供的文献信息。Key 默认仅保存在本次浏览器会话中；可由用户主动选择在本机设备保留。更换模型服务域名会要求重新确认并重新填写 Key。

预览面板固定在页面右侧，默认全高，可拖动上下边框调节高度。点击“缓存本文”保存已取得的信息；“下载缓存文章”打开管理页，可删除、排序，再导出一份包含 APA 风格引用和 BibTeX 的 Markdown，并尝试下载同编号的原文 PDF。下载遇到登录或认证时提示用户处理，不绕过访问限制。

当前版本不提供 JIF 或其他期刊影响力指标。原文下载由用户主动发起，不进行全文模型分析或自动搜索翻页，不能替代文献核对或学术判断。

## 权限用途

| 权限或访问范围 | 用途 |
| --- | --- |
| `storage` | 在本机保存设置、可选的 Key、生成缓存、主动收藏的论文及最近一次导出状态。 |
| `downloads` | 用户主动导出 Markdown 与原文、检查本批次下载状态；发现返回非 PDF 的无效文件时仅清理该批次刚创建的文件。 |
| `offscreen` | 在扩展自有隐藏页面的专用 Worker 中等待较慢的模型生成，避免 MV3 后台在长请求期间被终止。 |
| `https://scholar.google.com/scholar*` | 仅在 Google Scholar 搜索结果页识别标题并显示悬停卡片。 |
| `https://api.openalex.org/*` | 查询公开论文元数据与摘要。 |
| `https://api.crossref.org/*` | 在需要时补充公开 DOI 和元数据。 |
| 用户选择的 HTTPS 模型服务域名 | 仅在用户保存配置、授予该精确域名权限并同意后，发送论文标题与原文摘要以生成译文与概述。 |

## 审核者测试步骤

1. 按项目 README 加载已解压扩展，在 Chrome 扩展管理页确认扩展已启用且设置页可以打开。
2. 打开 `https://scholar.google.com/scholar?q=machine+learning`，将鼠标悬停在任一结果标题约半秒。确认右侧面板显示公开元数据与来源，默认全高，边框可调整高度。
3. 将鼠标移入卡片，确认卡片不会立即消失；使用“固定”可保留当前卡片；按 `Esc` 可关闭。
4. 在卡片中点击“设置”。不填写 API Key、不勾选同意项时，确认不会自动生成译文与概述。
5. 在设置页填写测试用的 HTTPS 模型服务地址、模型名称和用户自己的测试 Key。勾选外发同意项后保存，Chrome 应仅请求该模型域名的访问权限。拒绝权限后配置不应保存；再次保存并授权可继续测试。
6. 保存成功后返回 Scholar，确认扩展会向所配置服务请求译文与概述。生成和连接测试都可能由该模型服务计费。
7. 在设置页使用“清空缓存”和“清除密钥”，确认相应本机数据被移除。
8. 保存两篇论文后打开收藏管理页，调整顺序并导出，核对 Markdown 编号与 PDF 文件名前缀相同。确认下载失败有原因和原文链接，未取得的摘要或译文被标记为缺失。
